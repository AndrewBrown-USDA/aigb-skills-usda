# 13.1.1 -- metadata-contract
## Goal
Extend the dependency-free metadata normalization and validation contract for loadout fields while preserving legacy provenance records and existing validator behavior.
## TODO items
- [x] Define parser-compatible scalar normalization for `group`, `loadout`, required/optional dependency lists, and `version`, including trimming, ordering, and deduplication semantics.
- [x] Add identifier, empty-token, duplicate/overlap, self-reference, and canonical/legacy provenance alias validation while retaining current URL and required source metadata checks.
- [x] Add packaged-skill dependency reference validation at the validator integration point without changing catalog generation or install behavior.
- [x] Extend focused validator assertions for valid new metadata, malformed metadata, dependency/reference failures, provenance conflicts, and legacy compatibility.
- [x] Run the targeted checks `npm run validate:skills` and `npm run test:validate`, recording exact results and any deviations.
## Notes
The current parser accepts only scalar `metadata:` values; comma-separated dependency fields must remain scalar frontmatter. `skills/*/SKILL.md` remains authoritative, generated catalog files and packaged frontmatter are out of scope, and accepted ADRs 0001–0005 plus the install/sync boundary must be preserved. Existing `source_ref`/`upstream` aliases normalize to `upstream_ref`/`upstream_repo` but must agree when canonical fields are also present. Unknown dependency references must be reported during validation. No new dependencies or version-range grammar should be introduced.

## Final deviation/report
- Escalation regression root cause confirmed in `scripts/sync-skills.js` flow: lockfile `entry.version={status:"missing",value:null}` is first normalized to `version:null`, then revalidated via `validateMetadata(normalizeMetadata(entry))`, and prior validation logic rejected the normalized `null` sentinel.
- Minimal fix applied in `scripts/skill-metadata.js`: `validateMetadata` now treats `version:null` as valid when it is the legacy missing-version sentinel (both raw object form and normalized null form), while still rejecting explicit empty version strings.
- Tightly coupled guard assertions added in `scripts/validate-skills-test.js` for legacy missing-version acceptance through both direct and pre-normalized paths, plus explicit empty-string rejection.
- Validation evidence: `npm run validate:skills` passed (34 skills, 39 checks); `npm run test:validate` passed; `npm test` passed (smoke checks for 34 skills).
