## Goal
Extend `scripts/mine-history.js` so generated catalogs carry normalized loadout, dependency, and version metadata deterministically while rejecting invalid packaged metadata before output.

## Notes
`skills/*/SKILL.md` frontmatter is authoritative; `catalog/skills.lock.json` is generated and must not be hand-edited. The parser accepts scalar frontmatter metadata, so dependency lists remain comma-separated scalars. Preserve schema version 1 and legacy records with absent loadout fields, accepted provenance aliases, and the existing version `{status,value}` catalog shape. Do not touch `src/cli.js`, `scripts/install.js`, `scripts/skill-metadata.js`, `README.md`, or prior ADR/design documents. Preserve accepted ADRs 0001–0005 and the install/sync boundary. The 13.1.1 report confirms normalized `version:null` is valid for legacy missing-version records and unknown required/optional dependency references are validator failures.
