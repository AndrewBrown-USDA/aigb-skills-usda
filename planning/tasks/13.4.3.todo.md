# 13.4.3 -- measurement-tooling
## Goal
Create a reproducible, dependency-free measurement harness that compares the complete packaged corpus with defined loadout selections using installer-compatible traversal and records byte-based evidence without inventing token results.
## TODO items
- [x] Implement `scripts/measure-skill-loadouts.js` with `--help`, deterministic argument handling, pinned corpus/source-commit metadata, and an isolated output directory under `.scratch/loadout-measurement/`.
- [x] Assemble contexts from the packaged `skills/` tree using the installer/catalog source-path rules, preserving resolver order and recording selected roots, resolved names, omissions, and diagnostics.
- [x] Measure the required scenarios: full corpus, representative transitive loadout, the same loadout with one explicitly included optional dependency, and a minimal direct selection.
- [x] Run at least five serial samples per scenario in one invocation, retain every raw sample, and calculate median, minimum, maximum, spread, baseline/target bytes, absolute reduction, and reduction ratio.
- [x] Emit reproducible JSON evidence plus a Markdown summary linking the manifest, raw samples, calculation procedure/script, command arguments, environment, and source commit.
- [x] Mark tokenizer/model metrics unavailable and environment-dependent unless pinned tooling is actually available; do not estimate or publish token results.
- [x] Run the targeted `node scripts/measure-skill-loadouts.js --help` check and verify generated evidence is self-contained without modifying packaged skills, catalog, CLI, metadata, ADRs, or design documents.
## Notes
The integrated design requires fixed serialization/encoding and context assembly, a pinned complete `skills/` corpus, at least five clean serial samples per scenario, retained raw samples, and byte metrics with median/minimum/maximum/spread. Installer traversal currently reads the catalog, enumerates source directories, validates packaged `SKILL.md` paths, and materializes resolved entries; measurement must reuse those packaged source-path semantics and never use provenance URLs or upstream sources. Existing `.scratch/` artifacts are the appropriate disposable evidence location. Token counts depend on unavailable tokenizer/model services and must remain explicitly unavailable rather than inferred. The working tree already contains unrelated/in-scope prior-wave modifications; do not overwrite them.
