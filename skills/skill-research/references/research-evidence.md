# Research Evidence

Use this reference when gathering repository or ecosystem evidence.

## Source hierarchy

Prefer, in order:

1. Executable implementation and tests.
2. Current official specifications and documentation.
3. Recent issues, pull requests, and release notes.
4. Repository history.
5. READMEs and tutorials.
6. Third-party commentary.

## Claim handling

Label each substantive statement as **observed**, **inferred**, or **proposed**. For repository claims, record repository, full path, line range, immutable commit or ref, query or URL, inference status, and confidence.

Use an evidence table:

| Claim | Observation | Source type | Repository/path | Immutable ref | Lines or URL | Inference | Confidence |
|---|---|---|---|---|---|---|---|

Seek at least two independent signals for a proposed workflow gap. If a source is inaccessible or a search returns nothing, record the scope and failure state rather than treating it as proof of absence.
